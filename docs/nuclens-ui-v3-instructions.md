# Nuclens 화면 개편 — 코딩 에이전트 작업 지시서 (v2)

- 저장소: `wavyhairs/nuclens-v2`
- 참고 시안: `nuclens-today-mockup.html` (함께 전달함. 9월 15일 실제 데이터로 만든 모바일 '오늘' 화면)
- 작성 기준일: 2026-09-15

이 지시서는 **서로 독립된 두 트랙**으로 구성된다. 순서에 상관없이 진행할 수 있고, 한쪽이 늦어져도 다른 쪽이 막히지 않게 설계했다.

| 트랙 | 내용 | 수정 대상 | Gemini 호출 수 |
|---|---|---|---|
| **A. 화면 v3** | 모든 탭을 3단 구조로 통일 | `web/public/*` (+선택: `web/build_data.py`) | 변화 없음 |

두 트랙 모두 진행 중인 STEP 0~8 리팩터링 PR과 절대 섞지 않는다.

## 0. 왜 하는가

사용자 피드백은 "너무 복잡하고 글이 많다"이다. 모바일(390px)에서 실측한 결과, 정보량보다 **같은 내용의 반복**과 **카드마다 붙은 메타정보**가 주된 원인이다.

| 화면 (390px, 2026-09-15 데이터) | 세로 길이 | 글자(공백 제외) | 누를 수 있는 요소 |
|---|---|---|---|
| 오늘 | 7,530px | 3,690자 | 126 |
| 흐름 | 18,934px | 7,793자 | 182 |
| 장기 스토리 β | 9,847px | 3,778자 | 99 |
| 탐색 | 9,139px | 4,638자 | 84 |
| 보고서 | 9,808px | 4,791자 | 56 |

두 번째 원인은 문장 자체다. 현재 `why_important`는 150자 이내로 생성되기 때문에, 목록 한 줄에 넣으면 중간에 잘린다. 트랙 A는 화면 구조를, 트랙 B는 한 줄에 맞는 문장을 해결한다.

## 1. 공통 절대 원칙 (위반 시 작업 중단 후 보고)

1. 리팩터링 PR과 섞지 않는다. 브랜치는 트랙 A는 `ui-v3/*`, 트랙 B는 `copy-short/*`로 만든다.
2. `docs/REFACTOR_EXIT_CRITERIA.md`의 골든 픽스처와 characterization 테스트를 이 작업에서 수정하지 않는다. 트랙 B에서 불가피하게 기준값이 바뀌는 테스트는 §B-5에 명시한 것만 갱신한다.
3. **Gemini 호출 지점(callsite)을 새로 만들지 않는다.** 호출 횟수를 늘리는 설계가 필요하다고 판단되면 구현하지 말고 보고한다.
4. 데이터에 없는 문구를 프론트에서 지어내지 않는다. 필드가 비어 있으면 대체 필드나 빈 상태 문구를 쓴다.
5. 한 단계(Phase)는 PR 하나로 만든다. 각 PR은 해당 트랙의 완료 기준을 충족해야 병합한다.

# 트랙 A — 화면 v3

## A-1. 트랙 A 원칙

1. **기존 화면은 그대로 둔다.** 새 UI는 `?ui=v3` 플래그가 있을 때만 보인다. 플래그가 없으면 현재 동작과 픽셀 단위로 같아야 한다.
2. 파이프라인(`news_bot.py`, `daily_brief.py`, `weekly_bot.py`, 클러스터링·랭킹·dedup, 프롬프트, 상태 JSON 스키마, 텔레그램)은 수정하지 않는다.
3. 기존 계약을 지킨다.
   - 새 JSON은 반드시 `.catch()`로 감싼다. 파일이 없어도 화면 전체가 죽으면 안 된다(2026-08-01 빈 화면 사고 계약).
   - 부팅 중에는 나중에 자리를 차지할 요소 위에 아무것도 그리지 않는다(CLS 0.90 사고, index.html 주석 참조).
   - `/admin`과 그 미들웨어는 건드리지 않는다.
4. 새 화면 문구는 `app.js` 상단 `UI_V3_STRINGS` 객체 한 곳에 모은다(이후 문구 외부화 작업 PHASE_PLAN S3 대비).
5. **트랙 B 필드(`why_short`)가 없어도 완전히 동작해야 한다.** 필드가 있으면 쓰고, 없으면 대체 필드로 떨어진다(§A-2-1).

## A-2. 공통 컴포넌트: 3단 공개 구조

모든 탭의 이슈 표시는 이 컴포넌트 하나로 통일한다.

### A-2-1. 1단: 목록 행 (기본 상태)

변형은 세 가지다. **보이는 요소만 다르고, 누르면 같은 2단이 열린다.**

| 변형 | 보이는 것 | 사용처 |
|---|---|---|
| `rank` | 순위 숫자(큰 글씨), 제목, 한 줄 중요성, 출처 배지 1개, 지역 | 오늘 핵심 3건 |
| `change` | 제목, 이전 보도 한 줄, 변화 표시, (있으면) '보고 검토' 표시 | 진행 중 이슈의 변화 |
| `plain` | 제목, 지역 | 그 밖의 이슈, 탐색 결과, 보고서 목록 |

**필드 매핑 (이 순서를 반드시 지킬 것):**

- 제목: `title`
- 한 줄 중요성(`rank`): `why_short` → `why_important` → `summary` 순서로, 비어 있지 않은 첫 값을 쓴다. CSS `line-clamp: 2`로 자른다.
  - **`card_why`와 `implication`은 쓰지 않는다.** `card_why`에는 시사점 문장이 들어가는 경우가 있다(예: 9/15 MRA 건은 "…줄이기 위해서다"가 들어 있음).
- 이전 보도 한 줄(`change`): **Gemini 없이 코드로 만든다.**
  - 형식: `이전 {M월 D일}: {이전 제목}`, `line-clamp: 1`
  - 데이터: `change_log`의 마지막 항목에 있는 `prior_article_date`와 `prior_title`. `change_log`가 비어 있으면, 타임라인(§A-2-3)에서 최신 바로 앞 카드 기사의 날짜와 `title_kr`를 쓴다. 둘 다 없으면 이 줄을 생략한다.
  - `change_display`(이전 요약 → 이후 요약)는 1단에서 쓰지 않는다.
  - 참고: 시안에는 "새로: …"로 표시했지만 그 문장은 사람이 줄여 쓴 예시였다. 오늘의 변화는 제목이 이미 담고 있으므로, 비교 기준인 이전 보도를 보여주는 쪽으로 확정한다.
- 변화 표시(`change`): `change_log` 마지막 항목의 `kind`가 `minor`이면 '세부 변화', 그 외 값이면 '단계 변화'. 로그가 없으면 '후속 보도'.
- 출처 배지: `verification.label` 하나만 표시한다.
- 보고 검토 표시: `report_pick`이 비어 있지 않을 때만 붙인다.

1단에서 **표시하지 않는 것**은 지역·분야 태그 여러 개, 'n회 추적', AI 배지, 유형 태그(정책 결정 등), 원문·저장 버튼이다. 이것들은 2단이나 3단으로 옮긴다.

### A-2-2. 2단: 제자리 펼침

- 행 전체가 `<button aria-expanded>`이다. 다시 누르면 접힌다. **두 번째 탭에 다른 동작을 붙이지 않는다.**
- 펼침 내용은 모든 변형에서 같다.
  1. `summary`
  2. `open_question` (있을 때만, "다음에 확인할 것" 라벨)
  3. 추적 정보: `tracked_briefings > 1`이면 "{first_seen}부터 추적 중, 브리핑 {n}회", 아니면 "오늘 처음 잡힌 이슈"
  4. 버튼: **[전체 내용 보기]** (주 버튼), [원문] (`representative_article.url`, 새 탭), [저장] (기존 저장 로직 재사용)

### A-2-3. 3단: 전체 내용 시트 (바텀 시트)

아래에서 올라오는 모달 시트로 만든다. 페이지 이동이 아니다.

구성 순서:
1. 헤더 태그: `verification.label`, `region`, 첫 번째 `topics`의 한국어 라벨(`app.js` 상단 `TOPIC_LABELS` 재사용), `tags` 최대 3개
2. 제목(전체 `title`)과 대표 기사 날짜
3. 왜 중요한가: `why_important` (시트에서는 긴 원문을 쓴다. `why_short`는 쓰지 않는다)
4. 한수원 시사점: `implication`
5. 기사 내용: `detail` (비어 있으면 섹션 자체를 생략)
6. 다음에 확인할 것: `open_question` (비어 있으면 생략)
7. **타임라인**
8. **관련 기사**
9. 보도한 매체: `related_articles[].publisher` 중복 제거
10. 하단 고정 버튼: [저장] [원문 보기]

빈 값 규칙: 3·4번이 비어 있으면 "아직 작성되지 않음"을 흐린 글씨로 표시한다. 섹션을 숨기지 않는 이유는 품질검증 과정에서 누락을 드러내기 위해서다.

**타임라인** (데이터는 `issues.json`의 해당 `issue_id` 레코드):
- 항목: `related_articles` 중 `member_role === "card"`인 것을 `article_date` 최신순으로 정렬한다.
- 각 항목에는 날짜, `title_kr`, `publisher`를 표시한다. 가장 최근 항목에는 '최신' 표시를 붙인다.
- `change_log[]` 항목의 `title`과 같은 기사에는 '세부 변화'(kind=minor)나 '단계 변화'(그 외) 표시를 붙인다.
- 항목이 1개면 점 하나와 함께 "아직 이어진 보도가 없습니다. 후속 기사가 잡히면 여기에 쌓입니다."를 보여준다.
- **타임라인의 출처는 `issues.json` 하나로만 한다.** `threads.json`(장기 스토리)과 섞지 않는다(§A-6 참조).

**관련 기사**:
- `related_articles` 중 `member_role !== "card"`인 것을 최신순으로 정렬한다.
- 5건까지 보여주고, 나머지는 "{n}건 더 보기"로 접는다.
- 각 항목은 제목, 매체, 날짜를 보여주고 원문 링크(새 탭)로 연결한다.
- 0건이면 "대표 기사 외에 연결된 기사가 없습니다."를 표시한다.

시트 동작 요구사항:
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby`를 지정한다. 열리면 닫기 버튼으로 포커스를 옮기고, 닫히면 원래 버튼으로 포커스를 돌려준다.
- Esc 키, 배경 탭, × 버튼으로 닫힌다.
- **브라우저 뒤로가기로 시트가 닫혀야 한다.** 시트를 열 때 `history.pushState`, `popstate`에서 닫는다. 기존 `restoreIssueFromHistory`와 충돌하지 않게 한다.
- 시트가 열린 상태의 주소(`?ui=v3&issue={id}`)를 공유하면 시트가 열린 채로 복원된다. 기존 `issue` 파라미터 처리를 재사용한다.
- 시트가 열려 있는 동안 본문 스크롤을 잠근다. `prefers-reduced-motion`이면 애니메이션을 끈다.

## A-3. Phase A1 — 플래그 기반 마련

1. `restoreUrlState()`에서 `ui` 파라미터를 읽어 `state.ui`에 저장한다. 값은 `"v3"` 또는 `""`이다.
2. **`syncUrl()`이 URL을 state에서 매번 다시 만들기 때문에**, `state.ui`를 파라미터에 다시 써넣지 않으면 첫 상호작용에서 플래그가 사라진다. 반드시 `syncUrl()`에 `if (state.ui) params.set("ui", state.ui)`를 추가한다.
3. `state.ui === "v3"`일 때 `<body>`에 `ui-v3` 클래스를 붙인다. v3 전용 스타일은 전부 `body.ui-v3` 아래에 둔다.
4. v3 렌더러는 새 파일 `web/public/ui-v3.js`에 둔다. `app.js`에서는 분기 호출만 추가한다(예: `if (state.ui === "v3") return renderTodayV3(briefing);`). `app.js` 본문 로직은 최소한으로만 수정한다.
5. 3단 컴포넌트(§A-2)를 이 단계에서 만든다. 아직 어느 화면에도 붙이지 않고, 단위 테스트만 추가한다. 테스트에는 필드 대체 순서(`why_short` 유무, `change_log` 유무)를 반드시 포함한다.

**완료 기준**: 플래그 없이 접속하면 기존과 동일하다. `?ui=v3`로 접속한 뒤 탭 이동, 날짜 이동, 이슈 열기를 해도 주소에 `ui=v3`가 유지된다.

## A-4. Phase A2 — 오늘 화면

구조 (위에서 아래 순서, 참고 시안과 동일):

1. 날짜 이동 (‹ 날짜 ›) — 긴 `<select>`는 v3에서 숨기고, 날짜 목록은 날짜를 눌렀을 때 뜨는 선택창으로 옮긴다.
2. 제목 "오늘 먼저 볼 3건"과 한 줄 안내 "이슈 {issue_count}개 중 골랐습니다. 진행 중 이슈 {n}건에 변화가 있습니다."
3. **핵심 3건** (`rank` 변형): `briefings.json` 해당 날짜의 `highlight_issues` 순서를 그대로 쓴다. 현재 `app.js`는 이 필드를 읽지 않으므로 새로 읽는다.
4. 오디오: 한 줄짜리 "3분 브리핑 듣기" 버튼. 누르면 기존 플레이어(빠른·전문가 선택, 배속, 진행 바)를 펼친다. 기존 `renderAudioBrief` 로직을 재사용한다.
5. **진행 중 이슈의 변화** (`change` 변형): `status === "ongoing"`이면서 `change_kind`가 있는 이슈. 핵심 3건에 들어간 이슈는 제외한다.
6. **그 밖의 이슈** (`plain` 변형): 나머지. 5개까지 보여주고 "{n}개 더 보기"로 접는다.
7. "이번 주 흐름" 링크 한 줄 → 흐름 탭으로 이동한다.

제거 또는 이동할 것:
- '한 주의 원자력'(주간 리포트 블록) → 흐름 탭으로 옮긴다(Phase A3).
- '오늘의 검증 상태' 사이드 패널, evidence rail → v3에서는 숨긴다. 검증 정보는 헤더의 기존 '데이터 상태' 버튼이 맡는다.
- 정렬·필터 컨트롤 → v3 오늘 화면에서는 숨긴다(탐색 탭이 담당).
- 하단 탭: 오늘 / 흐름 / 탐색 / 보고서 4개. 장기 스토리 탭은 v3에서 숨긴다(Phase A4).

**중복 금지 규칙**: 한 `issue_id`는 오늘 화면 전체에서 한 번만 나온다. 테스트로 강제한다.

**목표치 (390px, 1단 기본 상태)**: 세로 2,500px 이하, 글자 1,000자 이하, 누를 수 있는 요소 40개 이하. (참고 시안 실측: 1,940px / 681자 / 24개)

## A-5. Phase A3 — 흐름 탭

현재 12개 섹션이 같은 내용을 여러 방식으로 반복한다. 주제 추이는 4주 흐름 막대, 주제별 주간 변화 그래프, 키워드 비교 표로 세 번 나오고, 국가 지도와 국가별 이슈 수도 같은 내용이다.

v3 기본 화면:
1. **이번 주 판세** (오늘 화면에서 옮겨온 주간 리포트)
   - 무엇이 바뀌었나: `policy_shifts[].what` 최대 3
   - 그래서 의미는: `policy_shifts[].so_what` 최대 3
   - 다음에 볼 것: `watchpoints[]` 최대 3
   - `weekly_intro` 해설은 "해설 펼치기"로 접는다.
2. **주제 흐름 차트 1개**: 기존 `renderTrendTopicFlow`('최근 몇 주, 어디로 움직였나')를 유지한다. 주제 행을 누르면 해당 주제 이슈 목록을 `plain` 행으로 보여준다.
3. **이번 주 움직인 이슈**: `change` 변형 행으로 보여준다.
4. **앞으로 무엇이 있나**: 기존 일정 달력에서 '다가오는 일정'만 기본 노출하고, '날짜까지는 안 나온 것'은 접는다.
5. **"데이터 더 보기"** (기본 접힘): 기간 흐름, 키워드 비교, 국가 지도·국가별 수, 주제별 주간 변화, 워드클라우드, 지난 브리핑. 기존 렌더러를 그대로 넣고, 펼칠 때 처음 렌더링한다(지연 렌더).

**목표치**: 기본 상태 세로 5,000px 이하, 누를 수 있는 요소 60개 이하.

## A-6. Phase A4 — 장기 스토리를 시트로 흡수

- v3에서는 장기 스토리 탭을 숨긴다. 이슈의 흐름은 3단 시트의 타임라인이 담당한다.
- 탐색 탭에 정렬 옵션 "오래 이어진 이슈"를 추가한다. 기준은 `issues.json`의 `first_seen`~`last_seen` 기간이다.
- **`threads.json`, `thread_ledger.py`, `thread_judge.py`는 수정하지 않는다.** 기존 `?view=longterm&th=` 딥링크로 들어오면, v3에서도 기존 장기 스토리 화면을 그대로 보여준다(링크가 깨지지 않게).
- 알려진 불일치(사람이 결정할 사항, §C-2): 같은 웨스팅하우스 건이 시트 타임라인(issues.json)에서는 9/7부터 3건인데, 장기 스토리(threads.json)에서는 8/19부터 7건이고 무관한 "러시아산 우라늄 수입 금지법" 기사가 섞여 있다. 에이전트는 **어느 엔진이 맞는지 판단하거나 수정하지 말고**, 불일치 사례를 PR 설명에 표로 남긴다.

## A-7. Phase A5 — 탐색·보고서 탭

**탐색**
- 첫 화면에는 검색창과 "지금 많이 등장하는 대상" 칩만 둔다. 검색어나 칩, 필터가 입력되기 전에는 결과 목록을 그리지 않는다(현재는 9,000px 이상이 곧바로 깔림).

**보고서**

## A-8. Phase A6 (선택, 별도 승인 후) — 첫 로딩 데이터 분할

# 트랙 B — 한 줄 문구 `why_short`

## B-1. 목적과 범위

목록 1단의 한 줄 중요성에 쓸 **짧은 문장 필드 하나**를 추가한다.

- 추가하는 필드는 `why_short` **하나뿐**이다. "이전 보도" 줄은 트랙 A에서 코드로 만들므로 생성하지 않는다.
- 기존 필드(`summary`, `why_important`, `implication`, `open_question`)의 프롬프트 규칙, 길이, 게이트는 **바꾸지 않는다.**
- 텔레그램 발송 문구, 오디오 대본, 주간 리포트는 이 필드를 쓰지 않는다(이번 범위 밖).

## B-2. 호출 수를 늘리지 않는 방식 (필수)

- `news_bot.py` 큐레이션은 기사 `BATCH_CHUNK = 15`건당 Gemini를 **1회** 호출하고, 한 번의 JSON 출력에 모든 필드를 담는다. `why_short`는 **이 출력 JSON에 필드를 하나 추가하는 방식으로만** 만든다.
- 금지 사항:
  - 짧게 줄이기 위한 별도 호출 추가
  - `build_data.py`나 `daily_brief.py`에서 Gemini를 부르는 방식
  - 과거 아카이브를 채우기 위한 재큐레이션(backfill). 과거 기사는 비워 두고, 화면이 대체 필드를 쓴다.
- 새 callsite가 생기지 않으므로 `docs/2026-09-09-gemini-observed-baseline.md`의 callsite 표에 행이 추가되면 안 된다.

## B-3. 프롬프트 변경 (`news_bot.py` 큐레이션 프롬프트)

출력 형식 JSON의 `"why_important"` 바로 다음 줄에 추가한다.

```
"why_short": "...",
```

필드 규칙 섹션의 `why_important` 설명 바로 아래에 다음 규칙을 추가한다(문구는 다듬어도 되지만 조건은 유지할 것).

```
- why_short: must_read만 작성. why_important의 핵심을 목록 한 줄용으로 줄인 것.
  · 공백 포함 45자 이내, 한 문장.
  · 명사형 종결(~함 / ~됨 / ~임)로 끝낼 것. "~다", "~요"로 끝내지 말 것.
  · 누가·무엇이 영향을 받는지 주어를 드러낼 것.
  · 수치는 1개까지만.
  · 금지: 목적을 설명하는 "~위해서임/~위한 것임", 제목을 다시 쓰는 문장,
    why_important 금지 어미와 같은 류("~시사함", "~기대됨", "~전망됨", "~중요함", "~필요함").
  · why_important가 빈 문자열이면 why_short도 빈 문자열.
  · 좋음: "국산 기자재 수출 시 성능검증 중복 부담이 줄어듦"
  · 나쁨: "국내 성능검증기관의 신뢰도를 높이기 위해서임" (목적 설명)
```

## B-4. 필드 전달 경로

아래 경로를 모두 따라가서 `why_short`가 끝까지 전달되게 한다. 각 지점의 기존 `why_important` 처리를 참고한다.

1. `news_bot.py` 정규화 딕셔너리: `why_important`와 **같은 게이트**를 통과시킨다. 대상은 `strip_unsourced_person_names`, `drop_unsupported_causal_interpretation`이다.
2. **새 검사 추가** (위반하면 빈 문자열로 만든다. 기사를 격리하거나 재호출하지 않는다):
   - 45자 초과
   - 명사형 종결이 아닌 경우
   - 금지 어미로 끝나는 경우
   - `why_short`가 `title_kr`과 지나치게 비슷한 경우(기존 유사도 유틸 재사용)
   - `why_important`가 비어 있는데 `why_short`만 있는 경우
3. `news_archive.py`: 아카이브 레코드 필드 목록(`why_important`가 있는 곳)에 추가한다.
4. `web/build_data.py`:
   - 이슈 레코드와 `briefings.json`·`issues.json` 산출물에 `why_short`를 추가한다.
   - `FALLBACK_WITHHELD_FIELDS`에 추가한다. 폴백 기사에서는 `why_important`처럼 보류해야 한다.
   - 대표 기사 선택 로직이 `why_important`를 고를 때 같은 기사의 `why_short`를 짝으로 가져온다. 서로 다른 기사의 문장이 섞이면 안 된다.
5. 스키마 변경은 **필드 추가만** 허용한다. 기존 필드의 이름, 타입, 의미는 바꾸지 않는다.

## B-5. 테스트와 기준값

- 새 단위 테스트:
  - B-4의 검사 규칙 (위반 사례별 1개 이상, 9/15 MRA 건 "~위해서다" 류를 포함)
  - 필드 누락 JSON(구버전 응답)이 들어와도 정상 처리되는지
  - 폴백 보류 동작
