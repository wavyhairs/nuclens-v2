# 웹 데이터 파일 크기 — Cloudflare 파일 상한 대응 (2026-10-15)

## 무슨 일이 있었나

2026-10-15 아침 카드뉴스가 부른 Deploy web(run 38648184063)이 웹 테스트 1건에서 멈췄다.
`test_deployed_files_are_not_approaching_the_limit` — `briefings.json` 20.2 MiB 가 Cloudflare Pages 파일 상한
25 MiB 의 80%(20 MiB) 경고선을 넘었다. 아침 브리핑 자체 배포는 이 테스트를 거치지 않아 통과했지만, 카드뉴스의
마지막 배포와 화면 코드 머지 배포가 모두 막히는 상태였다.

## 1. briefings.json — 날짜별 조각으로 분할 (PR #253)

| | 값 |
|---|---|
| 창 | 60일(`NEWS_WINDOW_DAYS`) — 날짜 수는 고정 |
| 하루치 | 첫 주 50~300 KB → 최근 30일 평균 400 KB, 10/14 431 KB (커지는 중) |
| 그대로 두면 | 한 달 뒤 60 × 0.4 MB ≈ 24 MB — 경고선 상시 초과, 상한까지 2 MB |

필드를 덜어내면 하루치가 커질 때 다시 닿는다. 그래서 크기를 날짜 수와 떼어 냈다: `briefings.json` 은 최근
14일만 이슈를 싣고(로컬 실측 20.8 MB → 5.7 MB), 모든 날짜가 `briefings/<날짜>-<지문>.json` 조각(최대 579 KiB)을
갖는다. 화면은 오래된 날짜를 열 때 그날 조각만 받는다. 다시 경고선에 닿으려면 하루치가 지금의 세 배를 넘어야 한다.

## 2. issues.json — 측정 결과, 지금은 나누지 않는다

| | 값 (10/14 빌드) |
|---|---|
| 크기 | 18.4 MB (17.6 MiB) — 경고선(20 MiB)까지 2.4 MiB |
| 창 | 60일 — `first_seen`·`last_seen` 모두 08-15~10-14. 기사 창을 따라 오래된 이슈가 빠진다 |
| 하루 새 이슈 | 8월 11.6 · 9월 12.5 · 10월 11.8건 — 평평 |
| 하루치 바이트 | 8월 0.33 · 9월 0.30 · 10월 0.27 MB — 줄어드는 중 |
| 무게 | `related_articles` 10.3 MB, `representative_article` 3.4 MB |

**판단.** briefings.json 과 달리 이미 **정상 상태(창이 꽉 찬 상태)** 에 있고 하루치가 커지지 않는다. 그래서 지금
나누지 않는다. 대신 다음을 남긴다.

- 경고 테스트가 그대로 조기 경보다. 경고선을 넘으면 배포가 멈추므로 상한(25 MiB, 여유 7 MiB)에 닿기 전에 안다.
- 넘으면 쓸 처방(측정 완료): `representative_article` 은 739개 이슈 **전부**에서 `related_articles` 안의 한 행과
  같은 기사다(같은 hash). 이 칸을 hash 참조로 바꾸면 3.4 MB(18%)가 준다 — 창이 고정이라 다시 자라지 않는 여유다.
  이 칸을 읽는 곳(화면·도구)을 그때 찾아 함께 바꾼다.
