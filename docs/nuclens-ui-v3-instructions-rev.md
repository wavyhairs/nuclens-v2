## 1. 공통 절대 원칙

원본 §1 의 5개를 그대로 유지하고 두 개를 더한다.

1. 리팩터링 PR과 섞지 않는다. 브랜치는 트랙 A `ui-v3/*`, 트랙 B `copy-short/*`.
2. `docs/REFACTOR_EXIT_CRITERIA.md` 의 골든 픽스처와 characterization 테스트를 수정하지 않는다.
   트랙 B에서 불가피한 기준값은 §B-5 에 명시한 것만 갱신한다.
3. **Gemini 호출 지점(callsite)을 새로 만들지 않는다.** 필요하다고 판단되면 구현하지 말고 보고한다.
4. 데이터에 없는 문구를 프론트에서 지어내지 않는다.
5. 한 단계(Phase)는 PR 하나.
6. **(신설) 표시 규칙의 폴백은 빌드 한 곳에만 둔다.** 프론트에서 `A || B || C` 로 필드를 고르지
   않는다. `build_data.py:3711` 이 이유를 이미 적어 두었다 — *"화면에서 or 폴백을 하면 이 계약이
   두 곳에 흩어져 드리프트한다."*
7. **(신설) 이미 배포된 화면 어휘를 새 화면에서 재정의하지 않는다.** 같은 낱말이 두 화면에서 다른
   뜻이 되면, 플래그로 화면을 둘로 나눈 이득보다 손해가 크다.

# 트랙 A — 화면 v3

## A-1. 트랙 A 원칙

원본 §A-1 의 1~4 를 유지한다. 5번만 바꾼다.

5. **~~트랙 B 필드(`why_short`)가 없어도 완전히 동작해야 한다~~ → 트랙 A는 `why_short` 를 직접
   읽지 않는다.** 화면은 `card_why` 하나만 읽고, `why_short` 를 그 자리에 태우는 일은 빌드가
   한다(§B-4). 따라서 트랙 A는 트랙 B의 완료를 기다리지 않는다.

## A-2. 공통 컴포넌트: 3단 공개 구조

### A-2-1. 1단: 목록 행 — **개정**

변형 세 가지(`rank` / `change` / `plain`)와 "보이는 것만 다르고 누르면 같은 2단이 열린다"는
원본 그대로.

**필드 매핑 (개정):**

- 제목: `title`
- **한 줄 중요성(`rank`): `card_why` 하나만 읽는다. 폴백 없음.**
  - `card_why` 가 빈 문자열이면 **그 줄을 통째로 생략한다.** `summary` 로 메우지 않는다 —
    `summary` 는 '무슨 일이 있었나'라서 '왜 중요한가' 라벨 아래 세우면 제목 재진술이 된다.
  - CSS `line-clamp: 2`.
  - `card_why` 는 `finalize_card_fields()`(`web/build_data.py:3664`)가 만든다. 이 함수는
    이미 ①제목 재진술 ②`change_display` 중복을 걸러 낸다(실측 `issue-aeda14d4` 사고로 생긴
    코드). **프론트가 다른 필드로 폴백하면 이 필터를 통째로 우회한다.**
  - `why_short`(트랙 B)는 이 함수의 **1순위 재료로 들어간다**(§B-4). 화면은 모른다.
- 이전 보도 한 줄(`change`): Gemini 없이 코드로 만든다.
  - 형식 `이전 {M월 D일}: {이전 제목}`, `line-clamp: 1`
  - 데이터: **`change_log[0]`** 의 `prior_article_date` 와 `prior_title`.
    **원본의 "마지막 항목"은 틀렸다** — `issue_change_log.build()` 는
    `entries.sort(..., reverse=True)` 로 끝나고 독스트링도 "변화 이력(**최신순**)"이다.
    마지막 항목을 쓰면 3회 움직인 이슈에서 3주 전 기사를 '이전 보도'로 세운다.
  - `change_log` 가 비어 있으면(실측 97%) 타임라인(§A-2-3)에서 최신 바로 앞 **card** 기사의
    `article_date` 와 `title_kr`. 둘 다 없으면 줄을 생략한다.
  - `change_display` 는 1단에서 쓰지 않는다.
- **변화 표시(`change`): 기존 어휘를 그대로 쓴다. 새 낱말을 만들지 않는다.**
  - `app.js:354` 가 이미 배포한 표: `{ material: "단계 이동", minor: "후속 보도" }`
  - `change_log[0].kind` 가 `material` 이면 '단계 이동', `minor` 면 '후속 보도'.
  - **`change_log` 가 없으면 라벨을 붙이지 않는다.**
  - 원본이 제안한 '세부 변화'(minor)는 쓰지 않는다. `issue_change_log.py` 가 라벨을 둘로 나눈
    이유를 직접 적어 두었다 — minor 는 *"진전이 있었는지 확인이 안 된다"* 는 뜻이고,
    *"'후속 보도'라 부르는 것은 사실이지만 '단계 이동'이라 부르는 것은 거짓"*. '세부 변화'는
    "작지만 변화는 있었다"를 주장하는 말이라 그 코드가 일부러 피한 거짓 주장이다. 또한 구 화면과
    v3 가 공존하는 동안 같은 이슈가 '후속 보도'와 '세부 변화'로 다르게 불린다(§1-7 위반).
- 출처 배지: `verification.label` 하나. **`label` 이 비어 있으면 배지를 생략한다** —
  `verificationState()`(`app.js:303`)의 폴백 경로가 만드는 객체에는 `label` 이 없다.
  - 주의(고치지 말 것): §C-1 의 '실제 매체 수와 배지 불일치'가 미해결인 채로, 1단에서는 이
    배지가 **유일한 신뢰 신호**가 된다. 사례를 발견하면 PR 설명에 적는다.
- 보고 검토 표시: `report_pick` 이 비어 있지 않을 때만.

1단에서 표시하지 않는 것은 원본 그대로(지역·분야 태그 여러 개, 'n회 추적', AI 배지, 유형 태그,
원문·저장 버튼).

### A-2-2. 2단: 제자리 펼침

원본 그대로. 행 전체가 `<button aria-expanded>`, 다시 누르면 접힘, 두 번째 탭에 다른 동작 없음.

펼침 내용: ①`summary` ②`open_question`(있을 때, "다음에 확인할 것") ③추적 정보
(`tracked_briefings > 1` 이면 "{first_seen}부터 추적 중, 브리핑 {n}회", 아니면 "오늘 처음
잡힌 이슈") ④버튼 [전체 내용 보기](주) · [원문] · [저장]

### A-2-3. 3단: 전체 내용 시트 — **개정**

바텀 시트. 페이지 이동이 아니다. 구성 순서·시트 동작 요구사항(포커스·Esc·pushState·스크롤 잠금·
`prefers-reduced-motion`)은 원본 그대로.

**개정 ①: 데이터 출처를 못박는다.**

> 3단이 읽는 레코드는 **반드시 카탈로그(`state.issues`)에서 `issue_id` 로 다시 찾은 것**이어야
> 한다. `briefing.issues[i]` 를 그대로 쓰면 안 된다.

이유는 실측이다. `briefings.json` 안에 내장된 이슈 레코드는 **그 회차 시점의** `related_articles`
를 들고 있고, 카탈로그의 누적본과 **734건 중 449건이 불일치**한다(최대 1건 vs 54건). 1·2단은
브리핑 레코드로 그려도 되지만, 3단의 타임라인·관련 기사·보도 매체를 브리핑 레코드로 그리면
**타임라인이 조용히 잘린 채 "아직 이어진 보도가 없습니다"로 보인다.** 그 증상은 데이터 결손과
구분되지 않으므로, 잘못 구현해도 화면만 보고는 알 수 없다. 테스트로 강제한다(§A-10-9).

**개정 ②: 빈 섹션 노출을 검수 모드로 분리한다.**

원본은 3·4번(왜 중요한가 / 한수원 시사점)이 비면 "아직 작성되지 않음"을 표시하고 섹션을 숨기지
말라고 한다. 이유("품질검증 과정에서 누락을 드러내기 위해")는 타당하지만 대상이 틀렸다.

- `why_important` 는 **82.3%** 가 빈 값이다. 시트에서 원문을 쓰라고 했으므로 전형적인 시트가
  "왜 중요한가: 아직 작성되지 않음"으로 열린다.
- 타임라인 항목이 1개뿐인 이슈가 **78.1%**, 비-card 관련 기사가 0건인 이슈가 **54.2%** 다.
- 즉 전형적인 시트가 빈칸 세 칸이 된다. '단순화'가 목표인 작업에서 이건 반대 방향이다.

개정:

- 일반 경로(`?ui=v3`): 값이 비면 **섹션을 숨긴다.**
- 검수 경로(`?ui=v3&qa=1`): 원본 규칙대로 "아직 작성되지 않음"을 흐린 글씨로 **전부 표시한다.**
- 누락 감시는 화면의 일이 아니다. `issue_audit.json`(6.2 MB)과 `/admin` 이 이미 그 일을 한다.
- **시트의 '왜 중요한가'는 `why_important` 를 쓴다(원본 유지).** `card_why` 는 1단 전용이다.
  `why_important` 가 비고 `implication` 이 있으면 '한수원 시사점'만 남는 것이 정상이다.

**개정 ③: 타임라인 1건은 결함이 아니다.**

`member_role === "card"` 필터는 **옳다. 바꾸지 않는다.** card 수(>1인 이슈 21.9%)는
`tracked_briefings>1`(20.0%)·서로 다른 `briefing_date`>1(20.0%)과 일치한다. 즉 card 는
"이 이슈가 브리핑에 실린 회차"이고, 이슈의 80%가 한 회차짜리라는 뜻이다. 제품의 모양이지
데이터 결손이 아니다.

- 항목이 1개면: 타임라인 섹션을 **접고** 한 줄로 대신한다 —
  "이 이슈는 {날짜} 브리핑 한 회차에 실렸습니다."
  원본의 "아직 이어진 보도가 없습니다. 후속 기사가 잡히면 여기에 쌓입니다."는 78%의 시트에
  붙는 사과문이 된다.
- 항목이 2개 이상이면 원본 그대로(날짜·`title_kr`·`publisher`, 최신 항목에 '최신' 표시,

## A-3. Phase A0 (신설) — 첫 렌더를 `news.json` 에서 뗀다

**플래그와 무관하다. `ui-v3` 밖이고, 구 화면에도 그대로 이득이다.** 먼저 한다.

`app.js:5458` 이 10개 파일을 `Promise.all` 로 묶어 첫 렌더를 전부 기다린다. 그중 가장 큰
`news.json` 은 raw 16.8 MB / gzip 2.65 MB 인데, **소비처가 둘뿐이다**:

- `renderNewsFeed()` — `app.js:2002`
- `renderTrendReadiness()` — `app.js:3057`, 이미 `pdata?.story_count ?? state.news.filter(...)` 로
  선계산 폴백을 갖고 있다

할 일:

1. `Promise.all` 에서 `news.json` 을 뺀다. `state.news = []` 로 시작한다.
2. 지연 로더 `ensureNews()` 를 만든다. `renderNewsFeed()` 진입 시와 뉴스 피드가 보이는 탭으로
   전환할 때 호출한다. 기존 계약대로 `.catch()` 로 감싼다 — 실패해도 화면이 죽지 않는다.
3. `renderTrendReadiness()` 는 `pdata?.story_count` 가 있으면 `state.news` 를 건드리지 않는다.
   없고 `state.news` 도 비었으면 그 수치만 감춘다(다른 항목은 그린다).
4. `build_data.py` 를 **건드리지 않는다.** 산출물 스키마 변화 0.

**완료 기준**: 첫 렌더까지 받는 gzip 바이트 약 4.7 MB → 2.1 MB 이하(-55%). 뉴스 피드가 여전히
뜬다. `render_smoke.mjs` 통과, 콘솔 오류 0. 기존 `web/tests/*.mjs` 와 python 테스트 전부 통과.

## A-4. Phase A1 — 플래그 기반 마련 (원본 A-3 개정)

1. `restoreUrlState()`(`app.js:964`)에서 `ui` 파라미터를 읽어 `state.ui` 에 저장한다(`"v3"` 또는 `""`).
2. `syncUrl()`(`app.js:938`)은 URL 을 state 에서 매번 다시 만든다. 반드시
   `if (state.ui) params.set("ui", state.ui)` 를 추가한다. 없으면 첫 상호작용에서 플래그가 사라진다.
3. **`ui-v3` 클래스는 `restoreUrlState()` 안에서, 그 자리에서 붙인다.**
   - 순서가 계약이다. `init()` 은 `restoreUrlState()`(5492) → … → `renderBriefing()`(1694 에서
     `booting` 해제) 순으로 흐른다. `booting` 동안 `.briefing-content-grid` 가 접혀 있으므로
     (`index.html:174`), **그 사이에 클래스를 붙이면 구 골격이 펼쳐진 채 그려지는 일이 없다.**
   - 늦게 붙이면 구 골격이 한 번 그려졌다가 사라진다. CLS 0.90 을 찍은 화면에서 같은 일이
     반복된다.
   - 실패 경로(`app.js:5435`)도 `booting` 을 걷는다. 그 경로에서도 클래스가 이미 붙어 있어야 한다.
4. **"app.js 에는 분기 호출만"은 사실과 다르다.** `index.html` 은 706줄짜리 고정 골격이고
   `app.js` 가 ID 로 채운다. v3 는:
   - `body.ui-v3` 아래에서 **구 골격을 CSS 로 통째 숨긴다**(`display:none`).
   - 새 컨테이너 `#v3Root` 를 `index.html` 에 하나 추가하고, 기본은 `hidden` 이다.
   - 렌더러는 새 파일 `web/public/ui-v3.js` 에 둔다. `app.js` 본문 수정은 최소로.
   - v3 전용 스타일은 전부 `body.ui-v3` 아래.
   - 새 화면 문구는 `UI_V3_STRINGS` 한 곳에 모은다(PHASE_PLAN S3 문구 외부화 대비). 원본 유지.
5. **v3 에서는 비활성 탭을 즉시 그리지 않는다.** `init()` 은 지금
   `renderBriefing / renderArchiveSearch / renderTrend / renderLongTerm / renderSaved` 를 전부
   즉시 호출한다(`app.js:5510~5516`). v3 는 어차피 구 골격을 숨기므로, 활성 탭 외에는
   탭 전환 시점으로 미룬다. 구 경로(`state.ui !== "v3"`)의 호출 순서는 **바꾸지 않는다.**
6. 3단 컴포넌트(§A-2)를 이 단계에서 만든다. 아직 어느 화면에도 붙이지 않고 단위 테스트만 추가한다.
   테스트에 반드시 포함할 것:
   - `card_why` 가 빈 값일 때 1단 한 줄이 **생략**되는가('summary 로 메우지 않는다')
   - `change_log` 유무 두 경로, 그리고 **`change_log[0]` 을 읽는가**
   - `change_log` 가 없을 때 변화 라벨이 **붙지 않는가**
   - `verification.label` 이 없을 때 배지가 생략되는가

**완료 기준**: 플래그 없이 접속하면 기존과 동일. `?ui=v3` 로 접속한 뒤 탭 이동·날짜 이동·이슈
열기를 해도 주소에 `ui=v3` 가 유지된다. v3 로 접속했을 때 구 골격이 한 프레임도 보이지 않는다.

# 트랙 B — 한 줄 문구 `why_short`

## B-1. 목적과 범위

원본 그대로. 추가 필드는 `why_short` 하나뿐, 기존 필드의 프롬프트 규칙·길이·게이트는 바꾸지
않는다, 텔레그램·오디오·주간 리포트는 이 필드를 쓰지 않는다.

**개정: 화면은 `why_short` 를 직접 읽지 않는다.** 이 필드의 목적지는 `card_why` 다(§B-4).

## B-2. 호출 수를 늘리지 않는 방식 (필수)

원본 그대로. `news_bot.py` 큐레이션은 `BATCH_CHUNK = 15`(`news_bot.py:1655`)건당 1회 호출이고,
`why_short` 는 **그 한 번의 JSON 출력에 필드를 하나 더하는 방식으로만** 만든다.

금지: 짧게 줄이기 위한 별도 호출 / `build_data.py`·`daily_brief.py` 에서의 Gemini 호출 /
과거 아카이브 backfill. `docs/2026-09-09-gemini-observed-baseline.md` 의 callsite 표에 행이
추가되면 안 된다.

## B-3. 프롬프트 변경

원본 그대로. 출력 JSON 의 `"why_important"` 바로 다음 줄에 `"why_short": "...",` 를 넣고,
필드 규칙에 원본 §B-3 의 블록을 그대로 추가한다(45자·명사형 종결·주어 노출·수치 1개·
목적 설명 금지·`why_important` 가 비면 `why_short` 도 빈 문자열).

## B-4. 필드 전달 경로 — **개정**

1. `news_bot.py` 정규화 딕셔너리: `why_important` 와 **같은 게이트**를 통과시킨다 —
   `strip_unsourced_person_names`(`news_bot.py:1379`),
   `drop_unsupported_causal_interpretation`(`news_bot.py:1290`).
2. **새 검사 추가** (위반하면 빈 문자열로 만든다. 격리·재호출 금지):
   45자 초과 / 명사형 종결이 아님 / 금지 어미 / `title_kr` 과 지나치게 유사(기존 유사도 유틸
   재사용) / `why_important` 가 비었는데 `why_short` 만 있음.
3. `news_archive.py`: 아카이브 레코드 필드 목록에 추가한다(`why_important` 가 있는 곳 —
   `news_archive.py:222`, 그리고 `318`·`324` 의 필드 튜플).
4. `web/build_data.py` — **여기가 원본과 다르다.**
   - 이슈 레코드와 `briefings.json`·`issues.json` 산출물에 `why_short` 를 싣는다(원본 유지).
     감사·재현용이다.
   - `FALLBACK_WITHHELD_FIELDS`(`web/build_data.py:778`)에 추가한다. 폴백 기사에서는
     `why_important` 처럼 보류한다(원본 유지).
   - 대표 기사 선택 로직이 `why_important` 를 고를 때 같은 기사의 `why_short` 를 짝으로
     가져온다. 서로 다른 기사의 문장이 섞이면 안 된다(원본 유지).
   - **(신설) `finalize_card_fields()`(`web/build_data.py:3664`)의 우선순위 맨 앞에 넣는다.**
     현재 `for candidate in (row.get("implication"), row.get("why_important")):` 을
     `(row.get("why_short"), row.get("implication"), row.get("why_important"))` 로 바꾼다.
     - 기존 필터는 그대로 적용된다 — 제목 재진술이거나 `change_display` 와 겹치면 다음
       후보로 넘어간다. 즉 `why_short` 가 제목을 다시 쓴 문장이면 자동으로 탈락하고
       `implication` 이 선다.
     - `finalize_card_fields` 는 `build_data.py:6813`(카탈로그)·`6815`(브리핑별) 두 곳에서
       호출되므로, 이 한 줄로 `briefings.json`·`issues.json` 양쪽의 `card_why` 가 함께 바뀐다.
       **새 배선은 필요 없다.**
     - 이 변경으로 구 화면의 `card_why` 도 함께 바뀐다. 의도된 것이다 — 구 화면 `app.js:1124`
       가 이미 `card_why` 를 읽는다. 다만 **§A-1-1 의 '플래그 없으면 픽셀 동일' 은 화면 코드에
       대한 약속이지 데이터에 대한 약속이 아니다.** 이 PR 의 스크린샷 비교는 `why_short` 가
       없는 고정 픽스처로 돌린다.
5. 스키마 변경은 **필드 추가만** 허용한다.

에이전트는 판단하지 않는다. 아래는 결정을 돕기 위한 정리이고, **권고는 참고일 뿐 근거 없이

   → `ranking_config.json` 영역이므로 이번 작업에서 수정하지 않는다. 다만 실측상
   `highlight_issues` 는 58회차 전부 정확히 3건이라 **구조적으로는 그대로 써도 안전하다.**

   그대로라 체감이 안 바뀐다(§A-6).
