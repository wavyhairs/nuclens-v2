# 「신규원전 공론화」 탭 — 방향성 검토 v1 (코드 변경 없음)

> 2026-10-15. 요청: 12차 전력수급기본계획을 위한 **신규원전 공론화** 관련 국내 기사를 3시간 크롤마다
> 계속 찾아 쌓고, 「해외 AI·DX」와 같은 인터페이스의 별도 메뉴로 보여 준다.
> 이 문서는 해외 AI·DX 레인(`docs/2026-10-14-overseas-ai-in-nuclear-tab-direction.md`)의 구조를 전제로,
> **같은 것·다른 것·정해야 할 것**을 가른다. §7 의 결정이 나면 §8 단계안대로 짓는다.

해외 AI·DX 와 같은 결론이다 — **수집은 되는데 노출이 안 된다.** 다른 점은 ① 전용 피드 없이도 공유 풀이 두껍다,
② 양이 AI 레인의 5~10배라 **같은 사건 묶기**가 화면의 성패를 가른다, ③ 주제가 시한부 절차(공론화 → 내년 상반기
정부안)라 **국면(stage)** 축이 필요하다.

### 0-1. 정정 — 위 표는 "기사 수"가 아니라 "접힌 뒤 대표 수"다 (2026-10-15, 사용자 지적)

메인 아카이브의 한 줄은 수집 단계 dedup(URL·제목 유사·임베딩)을 거친 **대표 1건**이고, 접힌 기사는 큐 레코드의
`raw_sources` 에만 남는다(`news_bot.py` 4188행). 아카이브 레코드에는 `raw_sources` 칸이 없다. 그래서 위 130건은
실제 기사 수가 아니다. 실측:

| 사건 | 아카이브 | 실제 기사 |
|---|---|---|
| 「정부, 원전 공론화 의제 확정…계속운전 등 제외」 10/15 | 1줄 | 대표 1 + 접힌 **22** (아시아경제·서울경제·연합뉴스·머니투데이…) |
| 「제12차 전력수급기본계획 위한 원전 공론화위원회 출범」 10/10 | 1줄 | 매체 **26곳** · 기사 30건 (delivery_log `story_outlet_count`) |
| 「기후부, 12차 전기본서 신규 원전 적정 설비 규모 결정 방침」 10/07 | 1줄 | 매체 25곳 · 기사 32건 |
| 최근 3일 큐(10/13~15)의 공론화·전기본 대표 12건 | 12줄 | 접힌 38건 — **4.2배** |

즉 큰 사건이 있는 날은 **기사 20~30건이 한 줄로 접혀** 보였고, 그래서 "하루 1~2건"처럼 읽혔다. 기사 단위로는
조용한 날 10~20건, 사건이 있는 날 50건 이상이다. 거기에 네이버 질의가 키워드당 **30건**(`display=30`)·6시간 창이라
「원전 공론화」 같은 뜨거운 키워드는 바쁜 날 잘린다. 이 정정이 설계에 미치는 것:

1. **공유 풀은 아카이브(대표)만으로 부족하다.** 접힌 `raw_sources` 까지 레인이 받아야 「매체 N곳」이 진짜가 되고
   사설·지역지 기사가 목록에 선다 → §2 의 풀 정의를 바꿨다.
2. **전용 네이버 질의는 `display=100`** (API 상한)으로, 창은 레인 창(3일) — 메인의 6시간·30건과 독립.
3. 화면 행 단위를 **사건**으로 둘지 **기사**로 둘지가 실제 결정 항목이다 → §7-9.
4. 추정 건수(§2) 를 고친다: 포함 **기사 10~50/일**, 묶은 뒤 **사건 2~8/일**.

### 3시간마다 화면에 띄우는 길은 이미 있다

`crawl.yml` 은 수집 → 레인 판정 → `build_data` → Pages 배포(`web-deploy` 스텝)를 매 회차 한다. 해외 AI·DX 탭은
그 결과를 **확정 회차(아침 브리핑 날짜)** 와 **「다음 브리핑에 실릴 기사」(pending)** 로 나눠 보인다. 새 레인도
같은 길을 타면 "3시간마다 검색해서 웹에 띄우기"는 추가 인프라 없이 된다. 다만 이 주제는 하루 안의 움직임
(의제 확정 보도 → 반발 → 해명)이 잦아 pending 패널의 위치·이름이 AI 탭보다 중요하다(§4-2).

## 2. 수집 — 공유 풀이 본체, 전용 질의는 보강

- **공유 풀 = 대표 + 접힌 기사** (§0-1 정정). 두 갈래로 받는다.
  - 최근 3일 메인 아카이브(대표, `recent_main_records` 그대로) — 메인 큐레이션의 `title_kr`·`summary`·`detail` 을 쓴다.
  - **이번 회차의 수집 후보 전량을 접기 전 상태로** — `news_bot.main` 이 `semantically_unique`(대표 + `raw_sources`)를
    레인에 넘긴다. 접힌 기사는 제목·요약·매체·주소뿐이라 레인 판정이 문장을 쓴다(전용 질의 기사와 같은 취급).
    noise 로 버려진 대표의 접힌 기사도 이 길로만 들어온다(큐에 안 실리고 아카이브엔 칸이 없다).
    대표와 접힌 기사의 관계(`folded_into: <대표 hash>`)를 레코드에 남겨 §5 묶기의 **확정 근거**로 쓴다 —
    메인이 같은 기사라고 본 것을 레인이 다시 묻지 않는다.
- **전용 질의**(메인 큐 진입 금지, 레인 상태만 사용):
  - 네이버 뉴스 API — 메인 `search_naver` 를 재사용하되 레인 어댑터(`kind: "naver"`)로 RSS 항목 모양에 맞춘다
    (`originallink`·`pubDate`·`<b>` 태그 제거). **`display=100`**(API 상한), 메인의 6시간 창·14일 seen 과 무관하게
    레인 창(3일)으로 받는다. 메인의 30건·6시간 창에서 잘린 기사가 여기서 들어온다.
    질의 후보: `공론화위원회 원전` · `신규원전 공론화` · `시민참여단 원전` · `원전 숙의` · `12차 전기본 원전` ·
    `전력수급기본계획 공론화` · `기후에너지환경부 원전` · `원전 공론화 반발` · `영덕 신규 원전` · `울진 신규 원전`.
    negative 는 쿼리에 붙이지 않는다(메인의 2026-08-06 교훈 — API 가 AND 로 묶는다).
  - Google 뉴스 KR (`hl=ko&gl=KR&ceid=KR:ko`, `when:1d`) 2~3개 — 네이버가 놓치는 지역지·전문지 보강.
    `fetch_rss` 그대로 쓴다.
- **본문**: 전용 질의 기사만 `article_body.fetch_bodies` 로 받아 판정 재료로 쓴다(저장하지 않는다 — AI 레인과 같은 저작권 원칙).
- **프리필터**(결정적, 재현율 쪽으로 넓게): **주제 어휘 ∧ 원전 어휘**.
  주제 어휘 = 공론화·공론화위·시민참여단·숙의·전기본·전력수급기본계획·신규 원전·신규원전·공청회·주민설명회·수용성·부지.
  원전 어휘 = 메인 프리필터와 같은 목록(원전·원자력·원자로·한수원·기후에너지환경부…).
  '공론화' 단독은 올리지 않는다(교정시설·데이터센터·약국이 걸린다).
- **건수 추정**(§0-1 반영): 풀 1,500~2,500(접힌 기사 포함) → 프리필터 40~120 → 판정 30~80 → **포함 기사 10~50/일**
  → 사건 묶기 뒤 **2~8 사건/일**. Gemini 호출 4~10/회차(8건 배치). 접힌 기사는 대표와 같은 판정을 **상속**시켜
  (대표가 포함이면 접힌 것도 포함, 분류도 복사) 호출을 아낀다 — 다시 묻는 것은 대표가 없는 전용 질의 기사뿐.
  메인 `QUOTA_EXHAUSTED` 면 건너뛰고 다음 회차가 이어서 묻는다(동일).

## 3. 판정 — 범위 정의와 분류 축 (가장 중요한 결정, §7-1·§7-3)

### 3-1. 범위

| | 내용 | 처리 |
|---|---|---|
| **핵심** | 12차 전기본을 위한 신규원전 공론화 자체 — 공론화위 구성·출범·회의·의제·절차, 시민참여단 모집·숙의·조사, 결과·권고, 정부안 반영·국회 보고, 각 주체의 공식 입장·반발 | 포함 |
| **인접 ①** | 12차 전기본의 **신규원전 규모·일정** (수요 전망 상향, 정부안 연기, 원전 적정 설비 결정 방침) | 포함, `track=egbp` |
| **인접 ②** | 신규원전 **부지·지역 수용성** (영덕 포스코 MOU 보류, 울진·삼척 유치, 지역 갈등·주민 반응) | 포함, `track=siting` |
| 제외 | 고준위 방폐장 공론화(울진 방폐장 공론화 등), 계속운전 수용성(공론화 의제에서 제외됨), 전기본 일반(LNG 전환·양수·송전망), 다른 분야의 공론화(교정시설·데이터센터·의료), 해외 공론화, 배경 한 줄 언급 | 제외 사유 코드로 남김 |

제외 사유: `hlw_deliberation` · `continued_operation` · `egbp_non_nuclear` · `other_deliberation` · `overseas` ·
`background_mention` · `not_nuclear`. 인접 ①②는 **스위치로 끌 수 있게** 레코드에 `track` 을 적는다 —
화면 칩 「전체 · 공론화 · 전기본 · 부지」가 그 값을 읽는다.

### 3-2. 분류 축 (AI 레인의 적용영역·성숙도·주체·기술 자리를 대신한다)

| 축 | 값 | 화면 자리 |
|---|---|---|
| `stage` 국면 | `demand_outlook`(수요전망·초안) · `committee_setup`(공론화위 구성·출범) · `agenda_design`(의제·절차 설계) · `panel_deliberation`(시민참여단 모집·숙의·조사) · `result`(결과·권고) · `plan_reflection`(정부안 반영·국회 보고·확정) · `siting_local`(부지·지역) · `aftermath`(후속·법·소송) | 목차 행의 대분류 칸(AI 의 적용영역 자리), 필터 칩 |
| `actor_type` 주체 | `government`(기후에너지환경부·산업부·총리실) · `committee`(공론화위원회) · `assembly`(국회·의원) · `local`(지자체·지역사회) · `industry`(한수원·원자력계·산업계) · `civic`(환경·시민단체) · `expert`(학계·연구기관) · `media`(사설·칼럼) | 목차 행의 지역 칸 자리, 상세 칩 |
| `stance` 입장 | `expand`(원전 확대·찬성) · `reduce`(축소·반대) · `process_critique`(절차·공정성 비판) · `neutral`(사실 보도) | 상세 칩, 목차 꼬리 칩 (AI 의 성숙도 자리) |
| `article_type` | `report`(보도) · `analysis`(해설·분석) · `editorial`(사설·칼럼·기고) · `interview` · `press_release`(보도자료 전재) | 「사설」·「해설」 플래그 (AI 의 「벤더 발표」 자리) |
| `significance` 0~3 | 3 = 공식 결정·일정 확정(의제 확정, 결과 발표, 정부안 확정) / 2 = 공식 회의·절차 진행·주요 주체의 공식 입장 / 1 = 개별 입장·지역 동향·해설 / 0 = 사설·배경 언급 | 점수 ×3 |
| `event_key` 사건키 | 20자 이내 한국어 사건 이름(「공론화위 1차 회의」·「의제 확정」·「영덕 MOU 보류」) | 같은 사건 묶기의 1차 키(§5) |
| `event_date` | 사건이 일어난/일어날 날짜(없으면 빈 값) | 타임라인·달력 연계 후보 |

문장(`title_kr`·`summary`·`why_important`·`implication`)은 AI 레인과 같은 규칙 — 공유 풀은 메인 사실 문장을
우선하고 해석 문장은 레인이 다시 쓴다. 여기서 `implication` 은 "한수원 시사점"이 아니라 **"공론화 절차에서
이 사건이 뜻하는 것"** 으로 묻는다(정부안 일정·의제 범위·여론 지형에 미치는 영향).

### 3-3. 결정적 가드 (AI 레인의 `domestic_guard` 반대 방향)

- `domestic_only`: 메인 `scope != "kr"` 이고 판정 `countries` 에 KR 이 없으면 제외.
- `topic_guard`: 프리필터가 `hlw`(고준위·방폐장) 표시만 붙이고 신규원전 어휘가 없으면 판정이 포함이라도 제외 — 울진 방폐장 공론화가 걸린 실측(10/14) 때문.
- `stale_by_url`: AI 레인과 동일.

## 4. 화면 — 인터페이스는 「해외 AI·DX」와 같다

### 4-1. 같은 것

- 상단·하단 탭, 머리(제목·회차 이동 ←/→/셀렉트·한 줄 안내), 하루/최근 7일 segmented, 필터 칩 줄, 목차 행(`tocRow`),
  푸터의 「지난 기사 전체 검색 →」, 「다음 브리핑에 실릴 기사」 패널, 기존 이슈 상세 대화상자, 탐색 탭 범위 버튼.
- 회차 = **아침 브리핑 날짜**(`ai_lane_web.round_date` 와 같은 마감). 날짜 목록은 사건이 있는 날만.
- 데이터 없으면 탭 숨김(`syncAiChrome` 과 같은 게이트). 누적 20건 게이트는 두지 않는다 — 백필만으로 넘는다.

### 4-2. 다른 것 (이 주제라서)

| 항목 | 해외 AI·DX | 공론화 |
|---|---|---|
| 목차 행 칸 | 국가 · 적용영역 · 성숙도 · 「벤더 발표」 | **국면** · 주체 · 입장 · 「사설」/「해설」 · 「매체 N곳」 |
| 필터 칩 | 범위(AI/DX) · 적용영역 · 성숙도 | **트랙**(공론화/전기본/부지) · 국면 · 주체 · 입장 |
| 한 줄 안내 | 이 회차 N · 7일 N · 누적 사건 | 같음 + **현재 국면** 한 마디(가장 최근 significance≥2 사건의 stage) |
| pending 패널 | 목록 아래 | **목록 위**, 이름 「오늘 들어온 기사 · 3시간마다 갱신 · 마지막 HH:MM」 — 사용자 요청의 핵심이 "계속 띄우기"라서 |
| 상세 칩 | 범위·성숙도·기술·주체 | 국면·주체·입장·기사유형·트랙 · 「원전 이슈에서 보기」(같은 hash 의 메인 이슈가 있을 때 1줄) |
| 기본 보기 | 오늘 회차 있으면 하루, 없으면 7일 | 같음 |

pending 을 위로 올리는 것 말고는 **코드 분기가 아니라 설정값**(칸 라벨·칩 종류·문구)이어야 한다 → §6 구현 방식.

### 4-3. 탐색 탭

`archiveScope` 에 `공론화`(`as=deliberation`) 추가. 조회 대상만 바뀌고 기간·검색어·정렬은 그대로.
주제 셀렉트에 국면 8종을 노출. 지역 필터는 `국내` 고정(숨김).

## 5. 같은 사건 묶기와 중요도 — AI 레인과 **다르게** 둬야 하는 두 곳

### 5-1. 묶기

AI 레인의 규칙(주체 겹침 ∧ 적용영역 같음 ∧ 30일)은 이 주제에서 **과병합**된다 — 주체가 거의 늘 「정부·공론화위」이고
국면이 몇 주 같다. 대신:

1. `title_key` 같으면 같은 사건(동일).
2. **`event_key` 정규화 키가 같고 `stage` 가 같고 7일 안**이면 같은 사건. 사건키는 LLM 이 내지만 묶기는 Python 의
   결정적 비교다(공백·조사 제거 후 완전 일치). 제목 유사도로 잇지 않는다(이 저장소의 오병합 교훈).
3. 2 가 과분할되는 쪽(같은 회의를 「1차 회의」·「첫 회의」로 다르게 부름)은 **관리자 병합 override** 로 고친다 —
   그러려면 `admin_overrides` 에 레인별 `merge`/`split` 종류가 필요하다. AI 레인 문서 §5 가 약속하고 **아직 안 만든**
   `ai_include/ai_exclude` 와 함께 한 번에 만든다(§8 의 2단계).

대표 = 회차 안에서 공식 원문 > 매체 등급 > 먼저 나온 것(동일). 「매체 N곳」 배지는 `story_outlet_count` 그대로.

### 5-2. 중요도 (회차 안 정렬, 결정적·설명 가능)

`significance×3 + 주체(정부·공론화위·국회 +2, 지자체·산업계·시민단체 +1, 학계 +1, 언론 0) + 기사유형(보도·해설 +1,
사설 0, 보도자료 전재 0) + 매체 수(2곳 +1, 4곳+ +2, 상한 +2) + 근거 구성(공식 원문 +1)`.
breakdown 을 `round_scores` 에 남긴다(동일). AI 레인과 달리 **매체 수**를 넣는 이유: 이 주제에서는 다매체 보도가
곧 그날의 큰 사건이다(공론화위 출범 10/10~11 에 전자신문·브릿지경제·한겨레·조선일보 등 8곳).

## 6. 구현 방식 — 복제가 아니라 **레인 사양(spec) 주입**

해외 AI·DX 코드는 세 파일(`ai_lane.py` 497 · `ai_lane_pipeline.py` 582 · `ai_lane_web.py` 454)과 테스트 1,002줄,
그리고 `app.js` 의 `renderAi` 계열 약 200줄이다. 선택지는 둘이다.

| | A. 복제해서 고친다 | **B. 사양 주입 (권장)** |
|---|---|---|
| 방법 | 세 파일 + 화면 코드를 복사해 이름·어휘·프롬프트·점수를 바꾼다 | `ai_lane_pipeline.run`·`ai_lane_web.build_payload` 에 `spec` 인자를 더해 **피드·프리필터·판정·가드·레코드 생성·묶기·점수·라벨**을 받게 하고, 기본값은 지금의 AI 사양으로 둔다. 공론화 레인은 `deliberation_lane.py` 한 파일(어휘·분류·프롬프트·묶기·점수)로 사양만 제공 |
| AI 레인 위험 | 0 | 작다 — 기본값이 AI 사양이고 기존 테스트 1,002줄이 회귀를 잡는다 |
| 세 번째 주제가 올 때 | 또 복제 | 사양 파일 하나 |
| 화면 | `renderAi` 복사 → `renderDeliberation` | `renderLane(laneKey)` 로 바꾸고 `LANES = {ai: {...}, deliberation: {...}}` 설정(파일명·탭 id·칸 라벨·칩 종류·문구·pending 위치)으로 분기. `state.ai*` 는 `state.lane[laneKey]` 로 |
| 분량(추정) | 새 코드 ~1,300줄 + 화면 300줄 | 일반화 diff ~300줄 + 사양 ~450줄 + 화면 리팩터 ~250줄 |

`run()` 은 이미 `state_file`·`archive_dir`·`fetch`·`body_fetcher`·`judge_call` 을 받고 `collect_feeds` 는 `sources` 를
받으므로 B 의 추가 주입점은 `prefilter`·`judge`·`guards`·`make_record`·`sources` 다섯 개다. `build_payload` 쪽은
`group_rows`·`score`·`labels`·`issue_id` 접두·필드 투영 네 개. 화면은 함수 이름에 `ai` 가 박힌 곳이 약 25곳이라
리팩터 범위가 분명하다(`aiIssues`·`aiRounds`·`aiTocRow`·`aiFilterChips`·`renderAi`·`renderAiPending`·`stepAiRound`·
`syncAiChrome`·`isAiIssueId`·`archivePool`).

**네이버 어댑터**만 새로 필요하다 — `collect_feeds` 가 `kind: "naver"` 소스를 만나면 `search_naver(query)` 를 불러
RSS 항목 모양(`title`·`link`·`raw_link`·`pub`·`publisher`·`description`)으로 바꾼다. `news_bot` 을 import 하지 않는
가드레일은 유지한다 — 호출자(`news_bot.main`)가 `search_naver` 를 `fetch_naver=` 로 넘긴다.

## 8. 단계안

| 단계 | 내용 | 산출 | 판단 |
|---|---|---|---|
| **0. 기준 고정** (반나절) | 메인 아카이브 9~10월에서 프리필터 후보 ~400건 추출, 층화 표본 60건 손라벨(범위 §3-1 · 국면 · 사건키). 판정 프롬프트 초안을 `tools/ai_lane_stage0.py` 와 같은 방식으로 돌려 정밀도·사건키 일치율 측정 | `eval_artifacts/deliberation/` | 정밀도 ≥ 85%, 같은 사건 묶기 오병합 0건이면 1단계 |
| **1. 레인 일반화 + 공론화 사양** (1~2일) | `ai_lane_pipeline`·`ai_lane_web` 에 spec 주입(기본값 = AI), `deliberation_lane.py`, 네이버 어댑터, 가드, `news_bot.main` 호출 추가, `crawl.yml`·`daily-brief.yml` 커밋 목록에 `deliberation_archive/`·`deliberation_state.json`, 백필 1회(2026-09-01~) | 아카이브 + 운영 로그 한 줄 | AI 레인 회귀 테스트 전부 통과, 첫 두 회차 실측(포함/제외/오판) |
| **2. 화면** (1~2일) | `renderAi` → `renderLane` + `LANES` 설정, 탭·탐색 범위·상세 칩, pending 위로, 흐름 탭 소절은 보류 | `deliberation_issues.json` · 탭 | 백필 데이터로 국면 타임라인이 읽히는가 |
| **3. 교정·보강** (운영하며) | `admin_overrides` 레인별 `include/exclude/merge`(AI 레인 미완 항목과 함께), 흐름 탭 「공론화 국면별 주간 건수」, 주간 판세 한 단락, significance=3 푸시 | 선택 | 2주 뒤 피드별 `included` 합계로 전용 질의 가지치기 |

**페이로드 크기 메모.** `ai_issues.json` 은 창 없이 전량을 싣는다. 공론화 레인은 하루 2~6 사건 × `related_articles`
라 6개월이면 수 MB 가 된다. `docs/2026-10-15-web-payload-size.md` 의 경고 테스트가 그대로 조기 경보이고, 넘으면
`briefings.json` 과 같은 날짜 조각 처방을 쓴다. 1단계에서는 창을 두지 않는다(측정 먼저).

**가드레일(두 레인 공통, 바꾸지 않는다).** 메인 상태 파일은 읽기만 · 전용 질의 기사는 메인 큐에 넣지 않음 · 판정
실패는 표식 없이 다음 회차 재시도(세 번 실패 시 포기) · 어떤 예외도 크롤을 멈추지 않음 · `news_bot` 을 import 하지 않음.
